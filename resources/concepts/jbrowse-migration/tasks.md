# JBrowse genome workspace — tasks

[Concept](concept.md). No implementation started. Delivery order is read-only migration, then independently gated extensions.

1. [ ] **Compatibility and feasibility.** Select compatible published releases; demonstrate a locally bundled plugin in the linear React component. Prototype existing evidence formats, worker/CSP behavior, teardown, and coordinate conversion. Measure startup, bundle size, memory, and navigation. Record Apollo and circular-view compatibility separately, including required host APIs/services and annotation-display limitations. Resolve the saved-configuration/citation migration before changing production code.
2. [ ] **Read-only replacement.** Integrate the linear component through the existing browser contract and preserve the concept's parity checklist across all current view builders. Verify visible failures, cancellation/teardown, resize, themes, selection synchronization, and scientific evidence manually while browser tests remain parked. Add proportionate allowed non-browser coverage for changed configuration, citation, and packaging contracts.
3. [ ] **Migration delivery.** Remove IGV dependencies, renderer patches, and obsolete runtime assets only after parity review. Update configuration compatibility, build/version reporting, citations, third-party licenses, package verification, general genome help, affected workflow READMEs/results guides, and changelog together. Preserve historical run metadata and citations. Run repository-required checks, including Python checks if workflow assets change. Record verification limits.
4. [ ] **Circular overview.** Following a positive feasibility result, integrate annotation features and review markers with locus selection and a return to the preserved linear view. Verify non-circular contigs are not described as circular genomes and unsupported tracks are explicit. If the component cannot provide useful annotation context, record the blocker and defer implementation instead of substituting chords.
5. [ ] **Apollo curation decision.** Demonstrate an editable gene, evidence context, draft reopening, and validated GFF3 export in the embedded host. With the annotation-review-decision owner, specify replacement-artifact acceptance, provenance, identity mappings, stale-draft refusal, and CLI/Snakemake boundaries. Record a go/no-go and any service/security proposal. Production editing requires an agreed extension to that concept and shared drafting infrastructure; do not implement an independent save path here.
